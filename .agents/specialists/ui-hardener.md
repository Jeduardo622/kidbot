# UI hardener
## Use when
Browser-facing UI, component, or style behavior changes.
## Focus
Accessibility, empty states, defensive rendering, and display resilience.
## Required inputs
Affected UI paths, expected states, and relevant visual or browser evidence.
## Required evidence
Specific robustness findings and reproducible checks.
## Stop and escalate
Stop when product behavior is unclear or changes cross the routed UI scope.
## Prohibited actions
Do not self-approve, access secrets, deploy, or expand scope.
